# Sweety

Blood glucose tracker. Users register, record readings for four daily slots, and
view daily, month-to-date and previous-month summaries. Every reading is scoped to
the logged-in user.

## Stack

- React 19 with Vite, plain CSS
- Express 5 on Node
- PostgreSQL hosted on Supabase
- bcrypt for password hashing, JWT for sessions

## Layout

```
client/    React app
server/    Express API
database/  schema.sql (run once in Supabase)
```

## Running locally

You need Node 20 or newer, npm, and a Supabase project.

### 1. Database

Open the Supabase SQL editor, paste `database/schema.sql` and run it. That creates
the `users` and `glucose_readings` tables. The schema is safe to run more than once.

### 2. API

```powershell
cd server
npm install
copy .env.example .env
```

Fill in `server/.env`:

```env
PORT=5000
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@db.YOUR_REF.supabase.co:5432/postgres?sslmode=require
JWT_SECRET=your_random_secret
JWT_EXPIRES_IN=1d
```

Generate the secret with:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Then start it:

```powershell
npm start
```

The API listens on `http://localhost:5000`. `GET /` returns a small health message.

### 3. Client

```powershell
cd client
npm install
copy .env.example .env
npm run dev
```

`client/.env` should contain `VITE_API_URL=http://localhost:5000`. The app runs on
`http://localhost:5173`. Run the API and the client at the same time.

### Sample data

`node src/seed.js` from `server/` creates a test account with a few readings:
`seedtest@sweety.test` / `SeedPass1!`. Running it again is harmless.

## Deployment

The frontend is hosted on Vercel and the API on Render. Both redeploy on every push
to `main`.

### Render (API)

1. Render dashboard, New, Blueprint, pick this repository.
2. `render.yaml` sets the root directory to `server` and runs `npm ci` and `npm start`.
3. Paste `DATABASE_URL` when asked. `JWT_SECRET` is generated by Render.
4. The service URL looks like `https://sweety-api.onrender.com`.

### Vercel (client)

1. Import the repository in Vercel.
2. Set the root directory to `client`. The build command and output directory are
   detected automatically.
3. Add `VITE_API_URL` with the Render URL, no trailing slash.
4. Deploy.

`VITE_API_URL` is baked into the bundle at build time, so redeploy after changing it.
`client/vercel.json` rewrites client routes such as `/dashboard` and `/reports` to
`index.html`.

## API

Register and login are the only public endpoints. The rest need
`Authorization: Bearer <token>`.

| Method | Path | Notes |
|---|---|---|
| POST | `/api/auth/register` | `{ name, email, password }`, returns token and user |
| POST | `/api/auth/login` | `{ email, password }`, returns token and user |
| GET | `/api/readings` | all readings for the current user |
| POST | `/api/readings` | `{ glucose_value, reading_date, reading_slot }` |
| PUT | `/api/readings/:id` | same body as create |
| DELETE | `/api/readings/:id` | removes one reading |
| GET | `/api/reports/daily` | optional `?date=YYYY-MM-DD`, defaults to today |
| GET | `/api/reports/month-to-date` | 1st of the current month to today |
| GET | `/api/reports/previous-month` | the previous calendar month |

Reading slots are `Morning (fasting)`, `After breakfast`, `After lunch` and
`After dinner`. `glucose_value` must be a whole number from 40 to 600, the date
cannot be in the future, and a user gets one reading per slot per day (a duplicate
returns 409).

Reports return `count`, `min`, `max` and `average`. When the period has no readings,
`count` is 0 and the other three are null.

## Notes

- The JWT is kept in `localStorage`. That is fine for this project; a production app
  would use httpOnly cookies.
- There is no email verification and no password reset.
- The free Render instance sleeps after about 15 minutes without traffic, so the
  first request afterwards can take up to a minute.

Built for a junior full stack developer assessment.
